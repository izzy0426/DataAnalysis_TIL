# 1️⃣ 전체 개념 복습

## WITH문 & 파티션

### WITH 구문

- 쿼리를 정의해서 재사용 가능

```sql
WITH name_a AS (
  SELECT
    col
  FROM Table
), name_b AS (
  SELECT
    col2
  FROM Table2
)
SELECT
  col
FROM name_a
```

- CTE(Common Table Expression)
- `SELECT` 구문에 이름을 정해주는 것과 유사
- 쿼리 내에서 반복적으로 사용 가능

### Partition

#### 장점

1. 쿼리 성능 향상
   - 전체 데이터를 스캔하는 것보다 파티션을 설정한 곳만 스캔하는 것이 더 빠름
2. 데이터 관리 용이성
   - 특정 일자의 데이터를 모두 변경하거나 삭제해야 할 때, 해당 파티션 단위로 처리할 수 있음
3. 비용
   - 파티션에 해당되는 데이터만 스캔해서 비용을 줄일 수 있음

## 🧩 문제 1

문제 링크: [여러 기준으로 정렬하기](https://school.programmers.co.kr/learn/courses/30/lessons/59404)

풀이 과정:

```
- 문제 요구사항: ANIMAL_INS 테이블에서 모든 동물의 아이디(ANIMAL_ID), 이름(NAME), 보호 시작일(DATETIME)을 조회하고, 이름 순으로 정렬하되 이름이 같으면 보호를 나중에 시작한 동물을 먼저 보여주기
- 첫 번째 정렬 기준: 이름(NAME) 오름차순 (사전 순)
- 두 번째 정렬 기준: 보호 시작일(DATETIME) 내림차순 (최근에 들어온 동물 먼저)
- 복습한 점: ORDER BY에 여러 컬럼을 쉼표로 나열하면 앞의 기준으로 먼저 정렬하고, 값이 같을 때만 다음 기준을 적용함. ASC/DESC는 컬럼마다 따로 지정해야 하며, 생략하면 기본값은 ASC
```

## 🧩 문제 2

문제 링크: [동명 동물 수 찾기](https://school.programmers.co.kr/learn/courses/30/lessons/59041)

풀이 과정:

```
- 그룹화 기준: 이름(NAME)
- 제외해야 하는 값: 이름이 없는 동물(NAME IS NULL) → WHERE NAME IS NOT NULL로 집계 전에 제외
- HAVING 조건: COUNT(NAME) >= 2 (같은 이름이 두 번 이상 쓰인 경우만)
- 복습한 점: WHERE는 GROUP BY 전에 행을 거르고, HAVING은 GROUP BY 후에 집계 결과를 거름. 그래서 NULL 제외는 WHERE에서, 횟수 조건은 HAVING에서 처리해야 함. 집계 함수(COUNT, SUM 등)는 WHERE에서 쓸 수 없고 HAVING에서만 쓸 수 있음
```

# 4️⃣ 최종 회고

7주 동안 SQL BASIC 과제를 진행하며 느낀 점을 자유롭게 작성해주세요.

```
1. SQL을 배우기 전과 비교했을 때 달라진 점: 예전에는 데이터를 전부 불러온 뒤 가공했다면, 이제는 결과 테이블을 먼저 예상하고 필요한 데이터만 골라 연결하는 방식으로 생각하게 되었다.
2. 가장 도움이 되었던 과제 또는 문제 유형: LEFT JOIN과 IS NULL로 한쪽에만 있는 데이터를 찾거나 날짜를 비교해 잘못 입력된 데이터를 찾는 문제가 실제 데이터 검증에 바로 쓸 수 있어 가장 도움이 되었다.
3. 가장 어려웠던 개념: WHERE와 HAVING이 각각 GROUP BY 전후에 적용된다는 점과 NULL이 0이나 공백과 다르게 처리된다는 점이 처음에는 헷갈렸다.
4. 앞으로 데이터 분석이나 프로젝트에서 SQL을 어떻게 활용해보고 싶은지: 팀 프로젝트에서 기업 보고서의 감축 목표와 정부 배출량 데이터를 기업 단위로 JOIN해 비교하고, 누락된 기업을 확인하는 데 활용해보고 싶다.
5. SQL BASIC 과제에 대한 피드백: 쿼리를 짜기 전에 테이블, JOIN key, 정렬 기준을 먼저 적게 한 형식 덕분에 문제를 구조적으로 정리하는 습관을 들일 수 있어 좋았다.
```
